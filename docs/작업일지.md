# 작업일지

## 2026-09-08 — 저장소 개시, v0.1.0 코어

### 배경
Ibis(서지·인용 관리 앱)의 과제 **T41**에서 갈라져 나왔다. 사용자 제안은 "국회도서관이
할 수 있는 법령 정보를 별도 옵션으로"였는데, 다른 세션(hwp-endnote-0e)의 실측에서
전제가 두 번 뒤집혔다:

1. 🔴 **국회도서관 21종에 국내 현행 법령이 없다**(외국법률번역DB만). 국내 법령은
   법제처 소관이다 — '법령'이라는 이름으로 국회도서관만 붙이면 사용자가
   「초·중등교육법」을 못 찾는다.
2. 🔴 **법제처 API 가 둘이고 서로 다른 물건이다.** data.go.kr 공유서비스는 목록 8종뿐이고
   본문도 판례도 없다. 조문 본문과 판례는 **DRF** 에만 있다.

→ 그래서 이 저장소는 **법제처 DRF 가 주축**이고, 국회도서관 쪽은 이미 있는
자매 저장소 `na-openapi-mcp` 가 맡는다(중복 구현하지 않는다). Ibis 는 둘 다 붙인다.

### 설계 결정 — 수집 단위는 인용 단위다 (사용자 지시)
서지 메타데이터에 맞아야 하고 학술 문헌에 인용 가능해야 하므로 **법령 하나가 문헌
하나**다. 조문은 인용 시 위치로 넣고, 조문 단위로 쪼개 색인하지 않는다.
「초·중등교육법」은 조문 135개짜리 문서지만 참고문헌에는 한 줄이다.

### 실측 (약 45회 호출)
T41 이 이미 카탈로그 커버리지를 전수 조사해 두었으므로(2026-09-08, 국회도서관 ~30회 ·
법제처 ~90회) **다시 재지 않았다.** 여기서 잰 것은 T41 에 없던 **봉투 모양**뿐이다 —
파서를 추정으로 쓰지 않으려면 필요했고, T41 의 탐침 스크립트는 커밋되지 않아 사라졌다.

잰 것과 결과는 [LAW_API_GUIDE.md](LAW_API_GUIDE.md) 에 표로 남겼다. 요약:

- **갈래마다 태그가 다르고 이름에서 유추할 수 없다.** `ordin` 의 레코드 태그는 `<law>`,
  `detc`·`trty` 는 대문자, `expc` 만 루트에 `…Search` 가 없다. 본문 파라미터도 `MST`/`ID`.
- **모든 실패가 HTTP 200 이다.** 없는 target 은 0바이트, 없는 식별자는 target 과 무관하게
  `<Law>일치하는 … 없습니다</Law>`.
- **`query` 를 빼면 전체 카탈로그**(현행법령 5,614건). 오류가 아니다.
- **`display` 500 · `page` 하드 상한 없음** — 국회도서관의 `pageno<=99` 와 다르다.
- **판례 본문은 데이터출처에 따라 없다**(대법원 ○ / 국세법령정보시스템 ✕).
- **같은 필드가 목록과 본문에서 다른 날짜 꼴**로 온다.

교차검증: 잰 건수가 T41 의 값과 전부 일치했고(자치법규 8,517 · 행정규칙 732 ·
법령해석례 579 · 판례 259 · 헌재 258 · 현행법령 159 · 조약 79), 초·중등교육법의
조문단위도 **135개로 같았다**(조문 119 + 장·절 표제 16).

### T41 의 '미해결 둘' 중 하나는 미해결이 아니었다
`lsHistory`·`couseLs` 가 `type=XML` 을 무시하고 HTML 을 주는 것은 **사실**이지 수수께끼가
아니다(응답으로 확인 — couseLs 는 lawService.do 에서 404 다). 둘 다 화면용 연계 정보이지
인용 가능한 문헌이 아니므로 범위 밖으로 두고, 호출하면 그 사실을 알려 준다.

남은 미확인은 **부처 1차 법령해석 target 코드** 하나다. 안내 페이지가 자바스크립트로
그려져 본문만 받아서는 링크를 얻을 수 없다 — 브라우저로 열어야 한다. 후보를 더 짐작해
호출을 태우지 않았다(T41 이 이미 9개를 시도해 전부 빈 응답이었다).

### 자매 저장소에서 물려받은 것 · 처음부터 피한 것
뼈대(config/models/parser/client/exporters/server/cli)와 원칙은 그대로 옮겼다.
`mcp<2` 상한, truststore, safe_name, stdio 고정, raise_for_status 금지 등.

**적대적 검토가 자매 저장소에서 잡은 것 중 둘은 설계 단계에서 막았다:**
- **미매핑 필드가 어디에도 안 나오는 문제** — 국회의안의 '제안이유 및 주요내용'(97%
  채워진 서술형 본문)이 그렇게 사라졌다. 이 저장소는 정규화 열 뒤에 **원본 필드를 열로
  승격**한다(실증: 수집 40건 → csv 24열, `데이터출처명=대법원`·`질의기관명=경기도교육청`이
  실제로 파일에 있다).
- **검색어 하나 실패 시 앞서 모은 것 전량 폐기** — 축마다 결과를 보존하고 실패는
  `failed_axes` 로 보고한다. 회귀로 고정(`test_one_failing_axis_does_not_discard_the_rest`).

⚠️ 반대로 **이식하면 안 되는 사실**도 있었다. 국회도서관의 `pageno<=99`, charset 없는
헤더(chardet 문자 깨짐), 하이라이트 마크업 위치는 이 API 에 해당하지 않는다.
"같은 회사가 만든 API 도 다르다"를 GUIDE 와 CLAUDE.md 에 못 박았다.

### 🔴 레지스트리 오류 3종 — 탐침이 잡았다
`eflaw`·`elaw`·`lsStmd` 는 `law` 계열과 같은 봉투이리라 **짐작**하고 레지스트리에 적었다.
셋 다 틀렸다:
- `lsStmd` 의 레코드 태그는 `<lsStmd>` 가 아니라 **`<law>`** — totalCnt 159 인데 0건 회수.
- `elaw` 의 본문 루트는 `<법령>` 이 아니라 **`<Law>`**, 그것도 '없음' 봉투와 같은 태그다.
  구조도 다르다(`InfSection`·`JoSection`·`ArSection`·`BylSection`).
- `eflaw` 본문은 `MST` 만으로는 **HTML** 이 온다. `efYd` 를 함께 줘야 XML 이다 —
  시행일법령은 같은 법령의 시행일별 판본이라 (MST, efYd) 가 신원이기 때문이다.

**짐작한 자리가 정확히 틀린 자리였다.** `scripts/probe_api.py envelopes` 를 먼저
만들어 둔 덕에 커밋 전에 드러났다. 이래서 탐침을 커밋한다.

### 🔴 자체 결함 3종 — 전부 그날 내가 넣은 것
1. **`조문내용` 만 읽어 본문의 70%를 잃었다.** 조문의 알맹이는 `항`·`호` 안에 있다
   (조문내용 39개는 조 표제 문장뿐, 항 36 · 호 21). 2,057자 / 실제 7,359자.
   **오류는 나지 않았다** — 조용히 줄었다. 자매 저장소의 `<recode>` 사고와 같은 종류다.
   실응답 픽스처로 조문 수와 글자수를 직접 붙드는 회귀를 넣었다.
2. **로그 scrubber 가 로깅을 터뜨렸다.** 모든 인자를 `str()` 로 바꿔
   `log.warning("재시도 %d/%d", 1, 3)` 이 `TypeError: %d format: a real number is
   required, not str` 를 냈다. 재시도 경고 경로가 실제로 숫자 인자를 쓴다. 회귀 추가.
3. **`numOfRows` 를 '요청한 페이지 크기'로 오해했다.** 실제로는 **반환 건수**다
   (display=100 · total=3 → numOfRows=3). 결과가 적을 때마다 "서버가 3으로 깎았다"는
   거짓 경고가 나고, 더 나쁘게는 페이지 크기를 3으로 줄여 이후 페이징이 기어갔다.
   **라이브 첫 실행에서 드러났다** — 단위 테스트로는 안 보였다.

교훈이 자매 저장소와 같은 문장으로 반복됐다: **문서 통과도, 테스트 통과도 정확성의
근거가 못 된다.** ①·③ 은 각각 실응답 픽스처와 라이브 실행이 잡았다.
